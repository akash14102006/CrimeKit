# AI GOVERNANCE POLICY

**Status:** Active  
**Version:** 1.0  
**Last Updated:** June 2026  
**Authority:** AI Governance Architect + Principal Architect + CTO

---

## PURPOSE

Establish standards and controls for the use of AI tools (GitHub Copilot, Cursor, Claude, Windsurf) in development to ensure code quality, security, maintainability, and appropriate human oversight.

---

## PRINCIPLES

✅ **Human in the Loop:** AI is a tool to augment, not replace, developer judgment  
✅ **Responsibility:** Developers remain accountable for AI-generated code  
✅ **Transparency:** AI involvement is documented and traceable  
✅ **Security First:** AI never creates security vulnerabilities  
✅ **Quality:** AI output meets same standards as human code  
✅ **Training:** Team continuously learns best practices  

---

## WHEN TO USE AI TOOLS

### ✅ APPROPRIATE USE

1. **Code Generation:**
   - Boilerplate code generation
   - Function and method implementation
   - Test code generation
   - API client generation
   - CRUD operation generation

2. **Code Improvement:**
   - Naming suggestions
   - Documentation generation
   - Code organization recommendations
   - Performance optimization hints
   - Refactoring suggestions

3. **Explanation:**
   - Understanding existing code
   - Architecture explanation
   - Pattern explanation
   - Technology research
   - Debugging help

4. **Documentation:**
   - API documentation
   - Comment generation
   - README generation
   - Architecture documentation
   - Changelog generation

---

### ❌ INAPPROPRIATE USE

1. **Security-Critical Code:**
   - Authentication mechanisms (without review)
   - Authorization policies (without review)
   - Encryption implementation (without review)
   - Cryptographic key generation
   - Security configuration

2. **Complex Business Logic:**
   - Without thorough understanding
   - Without clear specifications
   - For novel/untested algorithms
   - For performance-critical sections
   - For rarely-used edge cases

3. **Autonomous Decisions:**
   - Making pull requests without review
   - Merging code automatically
   - Deploying to production
   - Making architecture decisions
   - Changing dependencies

## CODE REVIEW REQUIREMENTS

### AI-Generated Code
- ✅ **Always** requires human code review
- ✅ Reviewer must understand the code
- ✅ Reviewer must verify correctness
- ✅ Reviewer must check for security issues
- ✅ Reviewer must validate tests

### AI-Suggested Changes
- ✅ **Always** requires human review
- ✅ Accept only if developer agrees
- ✅ Modify if needed
- ✅ Never auto-accept

### AI-Modified Code
- ✅ **Always** requires full code review
- ✅ Compare to original version
- ✅ Verify no unintended changes
- ✅ Validate behavior

## PROMPT ENGINEERING STANDARDS

### Prompt Quality

**DO:**
- ✅ Be specific and clear
- ✅ Provide context and constraints
- ✅ Include examples
- ✅ Specify expected output format
- ✅ Mention edge cases

**Example Good Prompt:**
```
Create a NestJS service that validates user input using Zod.
The service should:
1. Accept an email address
2. Validate email format using Zod schema
3. Throw ValidationError if invalid
4. Return { email: string, valid: boolean }

Use dependency injection for error handling.
Include unit tests using Jest.
```

**DON'T:**
- ❌ Vague requests
- ❌ "Just make it work"
- ❌ Over-reliance on AI understanding
- ❌ Skip important details
- ❌ Ignore security requirements

### For All AI-Generated Code

- [ ] **Correctness:** Does it solve the problem?
- [ ] **Consistency:** Matches codebase patterns?
- [ ] **Security:** No vulnerabilities introduced?
- [ ] **Performance:** Efficient implementation?
- [ ] **Maintainability:** Clear and understandable?
- [ ] **Testing:** Tests included and passing?
- [ ] **Documentation:** Properly documented?
- [ ] **Completeness:** All requirements covered?

### For Security-Sensitive Code

- [ ] **Authentication:** Secure implementation?
- [ ] **Authorization:** Proper access control?
- [ ] **Data Protection:** Encryption where needed?
- [ ] **Input Validation:** All inputs validated?
- [ ] **Error Handling:** Secure error messages?
- [ ] **Logging:** No sensitive data logged?
- [ ] **Dependencies:** No vulnerable packages?

### For Performance-Critical Code

- [ ] **Algorithm:** Correct complexity?
- [ ] **Memory:** No leaks or inefficiency?
- [ ] **Database:** No N+1 queries?
- [ ] **Caching:** Proper caching strategy?
- [ ] **Benchmarked:** Performance tested?

## DOCUMENTATION REQUIREMENTS

### Every AI-Generated Code Must Include

1. **Commit Message:**
   ```
   [AI-Generated] Brief description
   
   Generated by: [Tool name] v[version]
   Prompted by: [Developer name]
   Reviewed by: [Reviewer name]
   
   Verification: [Link to verification checklist]
   ```

2. **Code Comments:**
   ```
   // Generated by AI: [Tool name]
   // Purpose: [Purpose]
   // Manual review: [Yes/No]
   ```

3. **PR Description:**
   ```
   ## AI-Generated Code Notice
   This PR includes code generated by [AI Tool].
   
   Generated by: @developer
   Reviewed by: @reviewer
   
   Verification:
   - [ ] Functionality verified
   - [ ] Security reviewed
   - [ ] Tests passing
   - [ ] Documentation complete
   ```

## SECURITY REQUIREMENTS

### AI Tools Security Policy

1. **Secrets Management:**
   - ❌ Never paste secrets into AI tools
   - ❌ Never use API keys in prompts
   - ❌ Never share passwords or credentials
   - ✅ Use generic placeholders
   - ✅ Inject real secrets after generation

2. **Data Privacy:**
   - ❌ Don't share customer data
   - ❌ Don't share PII
   - ❌ Don't share health information
   - ✅ Use sanitized examples
   - ✅ Assume tools may retain input

3. **Intellectual Property:**
   - ✅ Verify generated code license
   - ✅ Ensure no GPL contamination
   - ✅ Document AI usage
   - ✅ Check for third-party patterns

## VIOLATIONS & ESCALATION

### Policy Violations

| Violation | Severity | Action | Escalation |
|-----------|----------|--------|------------|
| AI-generated secrets committed | CRITICAL | Revert, rotate secrets | Security team |
| No code review on AI code | HIGH | Re-review required | Team lead |
| AI code causes production issue | HIGH | Post-mortem | Principal Architect |
| AI tool used inappropriately | MEDIUM | Reminder, retraining | Team lead |
| Insufficient documentation | LOW | Add documentation | Code reviewer |
